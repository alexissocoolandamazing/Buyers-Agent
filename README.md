# Nook

A Brisbane suburb-selection prototype for exploring where to rent, buy or invest. Nook turns user preferences into ranked suburb shortlists using explicit scoring rules and seeded suburb profiles.

**Status:** Frontend prototype. Prices, rents, yields, scores and confidence labels are demonstration inputs, not verified market observations. The application does not use a trained machine-learning model or live property-data service.

## What the prototype demonstrates

- Separate rent, buy and invest journeys, each with its own scoring function.
- Budget, region and priority controls, with additional bedroom, property-type or risk preferences depending on the journey.
- A guided preference quiz that links into the relevant explorer.
- Ranked results with score summaries, explanation text and pagination.
- Side-by-side comparison of two or three suburbs in the rental explorer.
- Responsive components, motion with reduced-motion handling, and a methodology page with charts.

## How recommendations work

1. Start with the local suburb profiles in [`src/data/brisbaneSuburbs.ts`](src/data/brisbaneSuburbs.ts).
2. Apply the selected region and budget logic.
3. Calculate a score using the rent, buy or invest formula and the selected preferences.
4. Round and constrain scores to 1–100, then sort descending. Equal scores are ordered alphabetically by suburb name.
5. Display the ranked shortlist alongside predefined explanation text and matched signals.

The scoring implementation is in [`src/lib/recommendations.ts`](src/lib/recommendations.ts). Its `calculateRentScore`, `calculateBuyScore` and `calculateInvestScore` functions are the source of truth for the implemented weights. The formulas are hand-authored prototype heuristics; they have not been validated against property outcomes. Explanation text is supplied with the profiles rather than generated by AI.

## Run locally

Install a Node.js version compatible with Next.js 16 and npm, then run:

```bash
npm ci
npm run dev
```

Open [localhost:3000](http://localhost:3000).

| Route | Purpose |
| --- | --- |
| `/` | Introduction and preference quiz |
| `/rent` | Rental explorer and suburb comparison |
| `/buy` | Buyer explorer |
| `/invest` | Investor explorer |
| `/methodology` | Data assumptions, scoring overview and limitations |

### Available checks

```bash
npm run lint
npm run build
```

To serve a completed production build locally:

```bash
npm start
```

The current package scripts do not define an automated test suite. The application uses `next/font/google`, so a build may require access to Google Fonts.

## Data and limitations

- The suburb profiles contain seeded estimates and subjective scores for product testing. A label such as “High” confidence is also seeded; it is not a measured statistical confidence level.
- Official and live datasets mentioned on the methodology page are possible future sources, not completed integrations.
- Recommendations concern suburbs, not individual listings. They do not model street-level variation, flood overlays, building condition, school catchment boundaries or an individual's financial circumstances.
- The current implementation has no application database, account system or external property-data API.
- Rental comparison is implemented; the buy and invest explorers do not currently render the same comparison panel.
- Budget handling and ranking are prototype heuristics and need dedicated edge-case tests and evaluation before practical reliance.
- No verified hosted demo is supplied in this README. Run the prototype locally using the instructions above.

This repository demonstrates interface design and deterministic recommendation logic. It should not be used as financial, investment or property advice.
